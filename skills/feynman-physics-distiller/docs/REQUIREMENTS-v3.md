v2（`skill/`，candidate 级，已安装）的日志结论：形状与归因层实打实赢过原版（追问 / 前提不足 / 归因严格胜出，触发判别满分，单文件可用），但**物理正确层没有被规则管住**——哨兵-从零-02 升级臂无正锚的三个样本（r3a / r5 / r6）各在不同位置写出无条件的普遍性物理断言，修一处挪一处（S5：同一行为连续补丁 = 单元设计错）。根因是 v2 的认知习惯表给了模型"推广、分层、让惊讶可检查"的野心，却没给它检查这类断言的步骤：**规则加了野心，没加验证**。另：非物理越界在单文件臂三次未满足；6144 字节用满，无余量。证据：`.pipeline/05-battery-adjudication.md` R-30…R-39、`.pipeline/05-codex-final-反盲对照.md`、`skill/evals/runs/`。

## 2. 四项结构改动（v3 的定义）

### A. 主动回审取代被动提醒（P12 闭环 / H 系）
从零、伴读两个入口（以及归因入口中要写引号原话时）的长回答，在**同一轮**里分两遍：先成稿，再按固定清单重读自己的稿子并就地改，**只输出改后的回答，不输出清单与自审过程**。清单（六项，写死在 SKILL.md 或其直接指针文件里）：
1. 扩展段 / 收束段的普遍性断言（任何 / 一律 / 必然 / 只要…就）是否自带成立条件，或已在正文推导过；写不出条件就降级为"通常"或删。
2. 收束句只回到用户的目标句，不新增正文未推导的可迁移判据。
3. 新出现的定量说法逐个查量纲与极限。
4. 引号内"费曼原话"是否落到 sources.md 的 ID；落不到即改为未核实或删。
5. 段数与入口契约一致（追问 ≤3 自然段；直取一行）。
6. 结尾无邀请、无菜单、无"要不要再讲讲"。
代价上限：长回答 token +30% 以内；追问 / 直取不做回审（零成本）。这是 v3 对 R-34/R-38 的结构性回答，不是第三条"注意反例"。

### B. 按 S6 重排内容：失败背书的 gotcha 取代通用习惯
删除 v2 的"认知习惯"九行表（多为 opus/astra 默认行为，P11 结算）。SKILL.md 正文只保留：入口契约、回审清单、归因红线、边界指针、按需读取。每条保留的规则须指回 §3 的一个失败样本或 spec 的 failure_cost；通用最佳实践（"分清定义与经验""先隔离主效应"）一律不得进 SKILL.md，可留在 rules/method.md 供从零多段设计时读。

### C. 按 S2 重切三层
- L1 description：只放触发与边界，不复述工作流；≤ 320 字符目标。
- L2 SKILL.md：脊柱 + 每个 L3 文件一句指针（何时读）。**目标 ≤ 4600 字节**（硬上限 6144，留 ≥1500 字节余量给未来 gotcha 回填）。
- L3：`rules/` 中——`sources.md`（原样）、`attribution.md`（索引 + 契约 + 勘误表，可压缩）、`companion.md`、`conflict.md`、`lineage.md`、`method.md`（从零多段设计时读；guidance 用 split signal 决定是否再拆）、**新** `boundaries.md`（v2 SKILL.md 的边界节：量子 / 类比 / 守恒 / 数学 / 历史，按主题命中时读）。
- `exemplars.md` **移出 rules/**：试讲 A / B 与九个短案例只作评审正锚，放 `evals/anchors.md`，运行时不读（v2 里它 13 KB 几乎无人读，S2 指针失效；且是正锚泄露源 R-8）。
- 每个 L3 文件在 SKILL.md 必须能引到它的指针句，否则不得存在。

### D. 入口形状机检，LLM 评审改为条件购买（H2 / E12）
- 新增 `evals/check_shape.py`：对 `evals/runs/<轮>/*.md` 的回答正文做确定性形状判定——追问 ≤3 自然段且无"类比 / 打个比方"引入句；直取正文 ≤1 行（允许一个公式）；从零第一段含"要算 / 要解释 / 要区分 / 目标"之一且末段不出现正文未出现过的"只要…就"结构；非物理回答 ≤2 句且无题目列表、无"要不要 / 想听哪个"；所有入口结尾无邀请句式；伴读首段含卷章节定位。规则写在 cases.md 每案判据旁，机检判据与判据文字一致。
- LLM 盲评只评两个维度：**物理正确、归因零幻觉**（含硬失败判定）；形状以机检为准，LLM 不再评形状（省 v2 六成的评审开销）。校准题甲 / 乙、盲评包协议、机械对照表、正锚只给评审者——全部沿用 v2 的 `盲评包生成.py` 与 README 协议。
- `check_all.sh` 沿用 v2 的 98 条思路重建（资产比对基线仍是 `original/`），新增 check_shape 对最近一轮 runs 的机检汇总。
