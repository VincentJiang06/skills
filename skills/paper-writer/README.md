# paper-writer

> 输入一个**论文需求**(字数 / 引用风格 / 章节 / 学科)和/或一个**选题**,从头写出一篇**完整、合规**的论文;每条引用交给一个独立核查者逐条核对,核不实的如实标出。

[English](README.en.md) · **简体中文**

**做什么** —— 把需求 + 选题变成一篇可提交的论文:满足每一条声明的硬约束(长度 / 必需章节 / 引用格式,由脚本检查),引用只保留独立核查者确认「来源存在且撑得起这句话」的那些,其余标 `[SOURCE NEEDED]` 并在回复里逐条列出。一条编造的引用或抄袭段落不是"差稿",而是学术不端——这个不对称驱动整个设计。

**好在哪** ——
- **两条完整性铁律(常驻上下文,永不违反)**:绝不编造引用/引文/数据(查不到的来源标 `[SOURCE NEEDED]`,绝不发明);绝不抄袭(不把逐字/近逐字的他人文字当原创)。
- **独立引用核查在主干里(0.2.0 承重设计)**:形式门过了之后,派一个**全新上下文、非 fork** 的核查子 agent,只给它论文、引用清单和用户自带的来源池,不给作者的笔记和台账。它逐条查证并打标:SUPPORTED / OVERSTATED(来源是真的,但论文说得比来源强,比如把相关说成因果)/ MISATTRIBUTED / FABRICATED / UNSURE,只有 SUPPORTED 算 RESOLVED。作者只能把结论往下调,不能往上改;改过的条目再交一次新核查者,只一次。
- **台账完整性门(如实收窄)**:`scripts/extract_citations.py --verify verifier_ledger.json` 只检查台账**完整、内部一致**(每条都有终态结论,标了 SOURCE_NEEDED 的论文里确有标记)。它**不**证明来源存在,也看不出台账是谁写的——这由核查者负责,回复里写明是谁核的:「独立核查(同家族 fresh 实例)」、「自查,无独立核查者」或「只查了形式,存在性未核」。
- **形式门按风格解析(0.2.1)**:APA / Chicago / MLA 各按本风格放年份的位置取键,作者名可以是非 ASCII(Özdemir、王某某);`[1-3]`、`[1,4]` 这类合并编号能识别。取不到键的条目直接判失败,并以 `<UNKEYED:…>` 进核查清单,不会悄悄绕过独立核查。MLA 的「正文 → 引文目录」方向脚本判不了(`(Smith 12)` 和 `(Figure 2)` 同形),由作者自查。
- **客观 / 主观分叉(C5)**:客观骨架由确定性脚本查(`check_length` / `check_sections` / `check_citations`);主观维度(来源忠实、论证质量、学术腔)由 rubric + 独立判官评。
- **实测(0.1.0 时期)**:一次 demo 从「间隔重复/测试效应」选题产出 1323 词 APA7 论文,7 条引用由作者自己联网查证为真、0 编造。那时核查由写论文的同一个 agent 完成,这正是 0.2.0 要改的地方。

**什么时候用** —— 「帮我写一篇关于 X 的论文」·「写一篇…的学术论文」·「把这个需求/选题变成论文」;给定格式规范 + 选题时最佳。

**不适用** —— 润色 / 摘要 / humanize / fact-check 一篇**已有**论文(→ 各自的 sibling skill);无选题无需求的泛写作。

**装什么** —— 1 个 `SKILL.md` + 5 个 `references/`(诚信政策 / 引用风格 / 论文结构 / 主观 rubric / 核查者说明书 verifier-brief)+ 4 个确定性脚本(`scripts/`:长度 / 章节 / 引用格式 / 引用清单+台账完整性门,Python 标准库)+ eval harness。

**诚实注记(v0.2.0)** —— 0.1.0 把台账门的退出码说成草稿无从作假的保证,但台账是写论文的同一个 agent 自己填的,这句话不成立,0.2.0 已更正。核查者的独立性只到**实例档**(同一家族模型的全新上下文),不是跨厂商。宿主不能派子 agent 时退回自查,回复会标明。0.1.0 提交信息里提到的 2026-07-29 两臂对照找不到制品,按零信息处理;0.2.0 的两臂对照(E11)**尚未测**。
