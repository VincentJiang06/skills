# rules/memory-lifecycle.md — 记忆生命周期（增量 delta / 遗忘义务 / 验证锚 / 分流）

读这份的时机：**第三步动记忆之前**，以及第四步自检时。docs 侧的编辑纪律在 [sync-protocol.md](sync-protocol.md)，这份只管记忆层——记忆不是默认资产，是有生命周期、会变成负债的持久状态。

## 1. 增量 delta 优于全文重写

**默认动作：只改被本次会话教训命中的条目/文件。** 改哪条要能指认（条目要有身份：一课一文件 / 一条一小节）；指认不了就说明该先给条目分身份，而不是重写全文。

**禁止动作：「把 MEMORY.md 整个重写一遍让它更简洁」。** 迭代重写有两个实测失效模式：

- **brevity bias** —— 为了简洁而丢掉领域细节（具体命令、版本号、失败条件都是第一批被"精简"掉的）；
- **context collapse** —— 反复重写逐轮侵蚀细节，每一轮看起来都只掉一点，累积起来把记忆磨成正确但没用的空话。

**重组（跨条目重排 / 合并 / 重写索引）只允许由尺寸硬预算触发**（`MEMORY.md` > 200 行或 > 25KB；单条记忆 > 100 行），不允许"觉得有点乱"就重组。触发之后必须带**显式保留规则**——动手前点名这次重组里不许丢的东西（命令、版本号、路径、失败条件、绝对日期、踩坑的具体现象），否则模型重构时默认会压缩内容（condense-by-default）。

**精简 ≠ 压缩。** 压缩掉细粒度执行细节，正是记忆从资产变负债的典型路径。压不下去的内容不要在记忆内部越写越糊——按[毕业机制](graduation-mechanism.md)搬进 `docs/`（有版本管理、有 diff、有人复核），记忆侧只留一行指针。

**验收不看当场 diff**：重组后抽 3 条旧教训，问"它原来的细节还答得出吗"。当场 diff 看不出 collapse，时距后的可答性才看得出。

## 2. 遗忘义务：整理包含删除

**整理不是只加不减。** 三类条目必须处理掉：**过期**（事实已不成立）、**被证伪**、**被新证据推翻**。

处置二选一：

- **删除** —— 运行时记忆、流水账、一次性上下文、已完成的待办、被新版本取代的项目记忆。
- **墓碑** —— 有谱系的资产（`docs/`、KB、决策记录里被推翻的结论）不物理删除，改成"已被证伪 + 出处 + 日期"的标注保留。物理删掉会让"当初为什么这么定"的反向检查失去对象。

**淘汰要分两层，不能只用一层**：机械判据（长期未被引用 / 未被访问、时间久远、指向已删除的代码或路径）只做**候选筛**；删不删的**终审是语义判断**（这条现在还真吗？丢了下次会不会重蹈覆辙？）。只用机械判据会误删低频但高价值的条目。

**长期零删除本身是失活信号。** 本次同步的记忆变更里如果一条删除 / 墓碑都没有，在第五步摘要里明说并给理由（"本次无过期条目，上一次删除记录在 2026-07-12"）。连续多个周期零删除零墓碑 = 遗忘义务已经失活，回去重新审一遍，不要等它自己冒出来。

## 3. 验证锚：状态类事实重跑锚，不比对文字

**事实类条目**（测试结果、部署 / 上线状态、版本号、端口 / 路径、依赖版本）对账时的默认动作是**重跑它的验证锚**——跑那条命令、看那个文件在不在、比那个版本输出——**而不是**把记忆里的文字和文档里的文字对比。两份文字可以互相完全一致地一起过期。

**写入时就挂锚**：`测试套件全绿（锚：npm test，2026-07-31，34 passed）` 优于 `测试套件全绿`。没有锚的状态类断言，下一个会话没法采信也没法证伪。

**锚断链**（命令改名、文件迁移、脚本被删）→ 该条目标注 `needs_verification` 并降级使用：**不照抄进 `docs/` / `CLAUDE.md`**，也不要因为"看起来还对"就默认保留。

**冲突时的默认方向**：当前证据（代码、命令输出）> 记忆文字。记忆在事实判定里是背景，不是裁判。

**成本节律**：高频消费或高危的条目每次对账都重跑锚；低频条目按到期复验即可，不必全量重跑。

## 4. 运行时记忆 vs 制度化积累（分流）

运行时记忆的第一身份是**崩溃恢复**，不是知识积累。它只该留"丢了会让下一个会话重做或做错"的三类：

1. 当前任务断点（做到哪了、下一步是什么）；
2. 环境特有约束（这台机器 / 这个项目独有的坑）；
3. 已证伪的路径（防重蹈覆辙）。

**积累型内容**——可复用的教训、"系统怎么工作"的机制说明、决策结论——属于**有版本管理与复核的载体**：`docs/`、`CLAUDE.md`、`CHANGELOG`。滞留在记忆文件里的积累型内容既没人复核，也进不了其他人的视野，还占着恢复通道的位置。把它迁出去、记忆侧删掉或缩成一行指针，就是[毕业机制](graduation-mechanism.md)在做的事。

**BAD**：`MEMORY.md` 里 40 条"学到的最佳实践"，没有一条说明丢了会怎样。
**GOOD**：教训审查后写进 `docs/`，记忆侧只留指针；运行时记忆里躺着的是断点、环境约束、已证伪的路径。
