# reorganize-logic

> 当项目文档烂到「增量同步不值得」时，以代码为唯一事实源，从零重建一套设计契约 —— 而且绝不「绿但错」。

[English](README.en.md) · **简体中文**

**做什么** —— 把旧契约压成只读 context（绝不复制），从代码重新推导出架构图 + 结构图 + 明确的接口定义；过时遗留只在人工评审门（manifest）后删除，绝不自动删。可整项目，也可只锁定某个模块/目录。

**好在哪** ——
- 确定性、语言无关的门（`verify_contracts.mjs`）把每个文档化接口绑到真实的 file:line，并对契约漏掉的「被识别的导出」报错（见「已知局限」）。
- 覆盖按符号而不是按名字算：同一个名字在两个文件里各自定义，每个文件各要一行（或一条排除）；再导出（ESM/CommonJS 汇总、`.d.ts`）不用第二行。遍历文件时跳过依赖、虚拟环境、缓存目录，以及 git 自己判定为「已忽略且未跟踪」的路径（被跟踪的文件不会因为匹配忽略规则而被跳过），`src/build/` 这类源码目录照读；跳过了什么会打印在 `not read:` 一行里。
- 对模糊的近名匹配只**标记**交 agent 复核，而非盖章放行 —— 杜绝「绿但错」。
- 门只做骨架判断，不裁设计意图：把强导出符号列为内部必须在同一行写明**理由**；「它是不是公开接口」由非 fork 的 fresh reader 按排除判断卡对照代码逐条裁决（维持 / 推翻 / 不确定），不确定的交给你决定。
- 门无法通过时（只能写不真实的契约、改代码或改门，或某语言没有匹配器）会停下来上报，而不是硬凑绿灯；任务中途绝不改门脚本。
- 删除走 fail-closed：未知一律拦下，绝不静默跳过。
- 与 neat 区分：neat 是*增量同步*文档，本 skill 是*推倒重建*。

**已知局限（0.3.4）** ——
- 与已安装的 0.2.1 相比有一处有意的行为变化：git 判定为「已忽略且未跟踪」的文件不再读取（0.2.1 全读），每一处跳过都打印在 `not read:` 一行里；CLI 会在目标项目里调用 `git`。
- 根目录若在一个更大仓库里、而外层仓库的规则把根目录内容整片忽略（如 `archive/v1/*`），未跟踪的文件会全部被跳过，PASS 可能只基于被跟踪的那几个文件。请传一个自身就是仓库的根目录，并在相信 PASS 之前看一眼 `not read:` 一行。
- Python 文档字符串里第 0 列的 `name =` 会被当成已定义（与 0.2.1 相同）；Go 分组 `type ( … )` 块读不到；打印的 `extracted`/`ratio` 按名字计数，不按（名字，文件）计。
- 自 0.2.x 带来的边角问题（零符号面也判 PASS、注释里的 export 会被抽出、JS 里的 `class X` 被当成强导出等），完整清单与复现见 [CHANGELOG.md](CHANGELOG.md) 0.3.4、0.3.3 与 0.3.2 节。
- 当前状态：release candidate（发布前检查通过，无未关闭的 P0/P1；对抗测试只到同模型实例级独立）。
- 与裸模型对比（3 个用例）：本 skill 从未更不准确、从未改动遗留文档，但裸模型在三个用例里都更完整。

**什么时候用** —— 「reorganize/重写 logic」·「从代码重新推导一套契约」·「重写架构/结构/接口文档」；也可用 `/reorganize-logic` 显式调用。
**不适用** —— 增量同步 / 会话收尾（→ neat，最锐的边界：本 skill 会*删*遗留，不是保留并同步）；设计 agent loop（→ loop-constructor）；改实现代码（重建的是契约/文档层，不是逻辑）；没有既有契约的全新项目（无可清理）。
