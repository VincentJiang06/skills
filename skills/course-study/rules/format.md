何时读：跟课写到讲义里的**第一处公式**时读「数学公式（严格约定）」全节（十一条，硬约定，每节写完照它自查）；写到第一处表、图、想画示意图处、流水线时序、算法/过程页（伪代码候选）或 pdftotext 公式乱码时读对应节；用户要导出 PDF 前读全文；写第一份伴读前对整体形状不确定时读「固定小节骨架」节。追问/总结入口不读。

# 排版与标注约定

目标：读者一眼分得清「老师的原话 / 我的讲解 / 我的补充 / 考试信息」，导出 PDF 后不丢信息。只用 markdown 稳定子集：不用下划线、HTML 标签、emoji 做任何标记（HTML 例外为 rules/layout.md 的锚点与 rules/depth.md 的默认关闭折叠答案）。与 SKILL.md 压缩版冲突时以本文件为准。

## 引用讲义原话

blockquote，行首页码加粗，原文逐字（空白归一后与 pdftotext 一致），英文不翻译，一条引用一个 blockquote；翻译与讲解放在引用之后的正文里。页码 N 一律是 PDF 页号（`pdftotext -f N -l N` 翻到的页），不是讲义页脚的逻辑页号。

```markdown
> **p.4** What is the longest path (slowest instruction)? Load instruction!
```

blockquote 里不得意译、不得补全、不得把两句拼成一句。「speedup ≈ number of stages」这种改写放正文，不放 blockquote。引的是承载定义、结论、条件或问题的原句，不是幻灯片标题。一节里引用一般不超过讲解的三分之一（软提示；题面块不计入）；整页文字不整段引，引最能当锚的几句，其余转述。

### 公式乱码（D1-A）

pdftotext 把分式拆成几行（本语料实测的形态：`z = logit(p) = ln ( p ) 1−p`）、把上下标摊平、或把字形抽成 `(cid:27)` 这类占位符（本语料 26 份 PDF 里没出现过，但别的讲义会）时：在 blockquote 里用 `$…$` 重排成讲义的公式，并在引用后的正文第一句注明「公式按讲义重排」。不把乱码补全成通顺英文原话，也不原样保留乱码。

```markdown
> **p.42** We define logit (a.k.a. log-odds) of an event A as $\mathrm{logit}(p)=\ln \mathrm{odds}(p)=\ln\frac{p}{1-p}$ whose range is $(-\infty,+\infty)$.

公式按讲义重排。……
```

**图形记号要在渲染页上看。**这一页的内容本身是一张结构图——状态机与自动机、数据通路、时序、电路、树与图、几何坐标图——写「元素」之前先用 Read 工具把这一页渲染出来看。原因：`pdftotext` 只抽得出图上的文字标签，图形它一概抽不出——双圈（终态）、箭头的方向与单双向、打了叉的格子（已弹出、已作废）、虚线与实线、颜色与阴影都不在文本里，而这页的结论常常就写在这些记号上。只照标签抄，边一条不少，机器照样读错。状态机的「元素」逐项列：初态、全部终态、每条边的起点、终点与标签；别类图同理，把图形记号承载的信息写成字。渲染不可用时在「元素」行末写明「图形记号未能核对（只有文字标签）」，回复里另起一行「图形未核对：<文件> p.N（原因）」（页级告警，不进文件级的「未识别用途的 PDF」），不从标签推断哪个是终态、哪条是虚线。

**整页是一张位图时**（`pdftotext` 这一页只抽出一行标题，`pdfimages -list -f N -l N <pdf>` 显示一张占满版面的位图——CENG L11 p.16 就是这样）：先用 Read 工具直接读这一页（它能把 PDF 页渲染出来），照着看到的写「元素 / 看什么」三行。渲染不可用（工具读不了这个 PDF、或读回来看不清）时走第四条出路，写成一行，回复里同样另起一行「图形未核对：<文件> p.N（原因）」：

```markdown
图（p.16）：Memory Hierarchy Levels
本页正文为位图，无法读取图像内容
```

不许拿标题去推测图上画了什么——这一页宁可写「无法读取」，也不编元素。

## 示意图（我画的）

一张图比一段话清楚的地方才画：状态机与自动机、树和图算法一步步的状态、数据流与流水线、层级或包含关系、几何直觉（坐标小图）。没有配额，不为好看而画；纯定义页不画。图只写在 `.md` 里：不生成图片文件，不调外部绘图工具。

图前固定一行身份标注，空一行接围栏块：

````markdown
示意图（p.12，我画的，非讲义原图）：感知机从输入到输出的三步

```mermaid
flowchart LR
  x["输入 x"] -->|"乘权重 w"| z["加权和 z"]
  z --> y["输出 sign(z)"]
```
````

- 两种形式：围栏 `mermaid`，只用 `flowchart` / `graph` / `stateDiagram-v2` 三种；或围栏 `text` 的 ASCII 图（坐标小图、数组与树的逐步快照更适合它）。
- mermaid 写法：节点与状态的 id 只用 ASCII 字母数字，且不拿 `end` 当 id（实测解析报错）；标签凡含中文、空格、括号、标点，一律放进双引号——`A["距离 d(u)=3"]` 能画，`A[距离 d(u)=3]` 实测解析失败；边上文字写 `-->|"…"|`；状态图的中文说明写 `state "…" as q0` 或写在转移的 `:` 之后。图里不写 `$` 公式、不用 HTML、不设样式与主题。
- **图不许比文字多断言**：每个节点、每条箭头和它的方向，都来自讲义该页的原话，或来自已标明的「**补充**：」——与 rules/companion.md「机制类陈述须能指到讲义的某一句」是同一条纪律；图里自取的数字照样当场标明。图后的讲解用文字把图走一遍，渲染不出来的地方（PDF、纯文本）读者也不丢信息。
- 讲义**原图**仍按上一节写「图 / 元素 / 看什么」三行；示意图不替代它，可以紧跟其后。
- **重画讲义里已有的对象**（讲义那台状态机、那条数据通路）时与原图逐元素对齐：初态、每个终态、每条边与方向、每个标签——先按上一节在渲染页上看过原图再画，少画一个终态也算错。读者会照你的图去跑，不会回头翻原图。
- 示意图是我的讲解，不入记忆库。

## 数学公式（严格约定）

目标：同一份 `.md` 在 Typora、GitHub、Obsidian 三处都渲染得出来。读者用 Typora 时需在「偏好设置 → Markdown」里勾选「内联公式」。
下面十一条是硬约定，写完每一节就照着自查一遍（数一数 `$` 是否成对、花括号是否闭合、公式里有没有中文）。同时实际调用目标 Markdown/KaTeX 渲染器检查所有公式。存在且读过的检查脚本可用于验证；检查脚本与日志不混入公开笔记。

### ① 只有两种定界符

行内 `$…$`；块级 `$$` **开合各自独占一行**，块前块后各留一个空行。不用 `\(…\)`、`\[…\]`；不写单行 `$$…$$`；`$$` 块不进列表项、引用块、表格单元——要配列表就把块写在列表之后，引用讲义里的公式用行内 `$…$`。

```markdown
坏：- 代价函数：$$J(\Theta)=\sum_i (y_i-\hat y_i)^2$$

好：- 代价函数如下式。

$$
J(\Theta)=\sum_i (y_i-\hat y_i)^2
$$
```

### ② 行内公式卫生

开定界符后、闭定界符前不留空白；闭合的 `$` 后面不能紧跟字母或数字（加一个空格或标点）；公式内不换行；**正文里**的行内公式长度约 80 字符封顶，更长的改成 `$$` 块。多步计算链、推导链（连等三步以上）写成 `$$` 里的 `aligned` 块、一步一行，不塞进一条行内公式。
唯一的例外是 blockquote 里重排的讲义公式：`$$` 块按 ① 进不了引用块，所以引用里多长的公式也写成行内 `$…$`，不因为长就拆、就截、就改块——但引用后的正文要照旧把它讲开。

```markdown
坏：$ \hat y = X\Theta $，其中 $\Theta$的分量是参数，误差是 $e$2 倍。
好：$\hat y = X\Theta$，其中 $\Theta$ 的分量是参数，误差是 $e$ 的 2 倍。
坏：> **p.70** $$E(\Theta) = -\ln p(\Theta) = \cdots$$   ← 引用块里不许出现 $$
好：> **p.70** $E(\Theta) = -\ln p(\Theta) = \cdots$   ← 引用里的长公式照样写行内
```

### ③ 公式内不出现任何非 ASCII 字符

不写中文、不写 `×` `→` `≤` `≥` `≠` `…` `°`、不写全角括号和全角逗号。改用 `\times` `\to` `\le` `\ge` `\ne` `\ldots`；中文注解一律放到公式外面；单位写 `\,\mathrm{ns}` `\,\mathrm{KiB}`；`\text{}` 里只准放 ASCII 单词。

```markdown
坏：$\mathrm{CPI} = p_{\text{对}} \times 1 + p_{\text{错}} \times 3$，延迟 $4 ns$。
好：$\mathrm{CPI} = p_{\text{correct}}\cdot 1 + p_{\text{wrong}}\cdot 3$（下标分别是预测对、预测错的比例），延迟 $4\,\mathrm{ns}$。
```

### ④ 标题与文件头里不写公式

`#`…`######` 的标题行、以及文件头块（H1 后第一个连续 `>` 块：课程 / 本讲 / 定位 / 前后 / 承接，见 rules/layout.md）里都不出现 `$`；公式写进正文。改标题时只把公式搬走，标题上原有的页码区间、【新】/【延伸 Lnn p.X】/【已会】、「动画分页」这些标记一个不能少。

```markdown
坏：## 4. 定理：$X^TX$ 可逆当且仅当 $X$ 列线性无关（p.47–48）
好：## 4. 定理：X 转置乘 X 可逆当且仅当 X 列线性无关（p.47–48）
坏：### 算例：在 $z=x^2+y^2$ 上跑梯度下降（p.92–98，动画分页）  ← 标题里有公式
坏：### 五次迭代的图示（p.93–98）                              ← 公式搬走了，「动画分页」也跟着丢了
好：### 算例：在二次曲面上跑梯度下降（p.92–98，动画分页）      ← 公式搬走，标记原样留着
```

### ⑤ 表格

单元格里允许行内公式，但公式内**绝不出现 `|`**（条件概率用 `\mid`，绝对值用 `\lvert x\rvert`，范数用 `\lVert x\rVert`）；单元格里也不出现 `\\`、`\begin{…}` 和 `$$`。

```markdown
坏：| 后验 | $P(\hat y = 1|X)$ | 范数 | $\|\Theta\|_2$ |
好：| 后验 | $P(\hat y = 1 \mid X)$ | 范数 | $\lVert \Theta\rVert_2$ |
```

### ⑥ 环境只写在 `$$` 块里

只用 `aligned`、`cases`、`pmatrix`、`bmatrix` 四种；一律不写在行内公式里；`\\` 换行只能出现在这四种环境内部。多步推导用 `aligned` 配 `&=` 对齐等号。

```markdown
坏：设计矩阵是 $\begin{pmatrix}1 & x_1\\ 1 & x_2\end{pmatrix}$。

好：设计矩阵是

$$
\begin{pmatrix}
1 & x_1 \\
1 & x_2
\end{pmatrix}
$$
```

### ⑦ 花括号、分式、绝对值

多字符上下标一律加花括号：`2^{20}`、`10^{6}`、`x_{i,j}`、`\theta^{(i)}`（单字符如 `\log_2`、`X^T` 可不加，但 `X^TX` 这种写成 `X^{T}X` 更保险）；`\frac{}{}` 两个参数都带花括号；绝对值 `\lvert x\rvert`、范数 `\lVert x\rVert`；戴帽用 `\hat{}` `\bar{}`，粗体用 `\mathbf{}`，实数集用 `\mathbb{R}`。

```markdown
坏：$2^20$ 个地址，$\frac ab$，$|x|\le 1$，$e^-1$
好：$2^{20}$ 个地址，$\frac{a}{b}$，$\lvert x\rvert \le 1$，$e^{-1}$
```

### ⑧ 强调标记不与公式交叉

一段 `$…$` 要么整个在 `**…**` 里面，要么整个在外面，不许开合各在一边；公式内不出现 `*`（乘号写 `\cdot` 或 `\ast`，最优解写 `\Theta^{\ast}`）；闭合的 `$` 后面不紧跟 `_` 或 `^`。

```markdown
坏：**最优解 $\Theta^*$** 满足 **$J'(\Theta^*)=0$** 且 $\Theta$_1 已定。
好：**最优解** $\Theta^{\ast}$ 满足 $J'(\Theta^{\ast})=0$，且 $\Theta_1$ 已定。
```

### ⑨ 正文里的美元符与公式里的百分号

正文里要写美元符号写 `\$`（否则它会和后面的 `$` 配成一段公式）；公式里的百分号写 `\%`（裸的 `%` 在 KaTeX 里是注释，会把后半条公式吃掉）。

```markdown
坏：缺失率 $50%$，售价 $5 元。
好：缺失率 $50\%$，售价 \$5 元。
```

### ⑩ 引用里的讲义公式要重排成 LaTeX

blockquote 逐字引用的规矩管文字，公式必须渲染得出来：引用里的每条公式都放进 `$…$`，并按 ③ 换成全 ASCII。只要重排动了讲义的原样（补回被 pdftotext 拆散的分式、摊平的上下标、缺掉的括号），就在引用后的正文第一句写「公式按讲义重排」（题面块里写「公式按原题重排」）；讲义原样本来就是能渲染的线性写法（如 `CPU time = CPI × CC × IC`）、只是套上 `$…$` 并把 `×` 换成 `\times`，不必另加说明。讲义自己的排版含糊、重排有取舍时，在「公式按讲义重排」后面补一句说明取的是哪一种读法。

```markdown
坏：> **p.42** logit(p) = ln ( p ) 1−p  whose range is (−∞, +∞).
好：> **p.42** We define logit of an event A as $\mathrm{logit}(p)=\ln\left(\frac{p}{1-p}\right)$ whose range is $(-\infty,+\infty)$.
```

### ⑪ 每条公式都要过 KaTeX

实际调用 KaTeX，以 `throwOnError: true` 为错误门槛，并按目标站点 strict 配置检查警告。不写 `\newcommand`、`\def`、`\renewcommand`，不用 KaTeX 内置以外的宏包命令（`\bm` 改 `\boldsymbol`）。执行渲染后另自查三件事：`$` 成对、花括号成对、每个反斜杠命令都是自己认识的 KaTeX 命令——拿不准的命令就换成认得的写法，不赌。
