# 学科画像：调焦，不是模板

画像只调「为什么是这样」与「考试怎么考」的重心；来源、粒度、引用、附录、记忆库纪律不随画像变；具体解释和检验方法按学科适配，不把历史论证当数值推导。不按学科选模板、不写 if/elif 分支；一讲可以跨画像。画像判断是推断，不写入记忆库。

## 学科画像

**硬件 / 体系结构（算题课）**——例：CENG3420。讲义特征：表格、时序、数据通路图、指令示例、给数字的例题。「为什么」的重心：把表算完、把图上每条线说清、指令逐条走一遍；学生卡的地方通常是「这个数怎么来的」「这条线接到哪」。典型考法（一律 C 级素材，措辞「常见考法是……」）：给参数算周期/加速比/命中率、画或改数据通路、追踪一段指令的流水线时序、数 stall。

**ML / 统计（推导课）**——例：ESTR3108 L2–L8。讲义特征：公式链、优化目标、几何直观、动画分页逐步展开一个推导。「为什么」的重心：推导链每一步的理由、每个符号的含义与取值范围、凸性/可逆性/单调性这类让推导成立的条件；学生卡的地方通常是「这步怎么从上一步来的」「这个条件为什么需要」。典型考法：写出推导（logistic 回归的梯度）、判断条件是否成立、解释超参数（学习率、正则化系数）的影响、比较两种模型的假设。

**算法 / 搜索（模拟课）**——例：ESTR3108 L9–L10。讲义特征：伪代码、状态图、复杂度表、小例子。「为什么」的重心：用一个小实例手工跑算法、复杂度从哪来、每个数据结构为什么选它；学生卡的地方通常是「展开顺序为什么是这个」。典型考法：手工模拟展开顺序、比较算法性质（完备/最优/时间/空间复杂度）、判断启发式是否可采纳。

**编程 / 操作系统 / 软件实验**——先交代输入、输出、环境与语言版本，逐行解释关键状态变化，跟踪栈、堆、进程、线程、文件描述符或网络连接等实际涉及的资源；分清创建、共享、所有权、阻塞、释放、异常路径。用一个可复现小输入追踪执行，说明输出可能次序与不变量、错误如何定位、修复依据和代价；不只贴代码、不把未运行示例称已验证。

**历史 / 人文 / 通识**——先交代时间、地点、行动者与语境，定义概念并区分历史语境与今天用法。把事实陈述、材料中的观点、作者解释、自己的推论分开；说明史料是谁在何时为何写的、能支持什么及遗漏什么。以具体事件、文本或图像走完“问题→证据→推论→限度”，比较至少实际相关的替代解释；不把先后当因果，不把一个人物或个案当整个群体，不为凑算例编历史数字。争议问题允许有条件的多种论证，自测检验用证据论证的能力，不制造唯一标准答案。
